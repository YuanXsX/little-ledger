# 04 · 接口设计（RESTful API）

> 版本：v1.0　|　日期：2026-10-21　|　基础路径 `/api`

## 1. 通用约定

### 1.1 统一返回结构

```json
{ "code": 200, "message": "success", "data": {} }
```

### 1.2 错误码

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 业务错误 / 参数校验失败 |
| 401 | 未登录 / 登录过期 |
| 403 | 无操作权限 |
| 500 | 系统内部错误 |

### 1.3 分页规范

请求参数 `page`(从1开始)、`size`；返回 `data` 内为 `{ list: [], total: N }`。

### 1.4 鉴权

除 `登录`、`健康检查` 外，其余接口需携带 `Authorization: Bearer <JWT>`。

## 3. 关键接口示例

### 3.1 登录

```
POST /api/auth/login
请求：{ "username": "admin", "password": "***" }
响应：{ "code":200, "data": { "token":"<JWT>", "user":{...} } }
失败：{ "code":400, "message":"账号或密码错误(剩余次数 2)" }
锁定：{ "code":400, "message":"连续失败 3 次，账号已锁定" }
```

### 3.2 财务流水录入（重复校验）

```
POST /api/finance-ledger
请求：{ "voucherNo":"C202506001", "flowType":"收入", "amount":12800.00,
        "occurDate":"2025-06-02", "payMethod":"银行转账", ... }
重复：{ "code":400, "message":"该凭证号+金额+日期已存在，请勿重复录入" }
```

### 3.3 越权拦截

```
响应：{ "code":403, "message":"无此操作权限，请联系管理员" }
```

## 4. 设计说明

- 删除类敏感操作统一要求前端二次确认 + 后端二次验证（登录密码）
- 脱敏字段在**出参层**统一处理，接口不返回明文手机号/邮箱
- AI 问答接口预留流式输出（`text/event-stream`），超时降级返回检索原文
